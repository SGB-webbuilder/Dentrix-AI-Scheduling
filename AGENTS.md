# Repository instruction entrypoint — preparation candidate

This file is a repository-local safety entrypoint for the prepared scaffold. It does not claim a validated binding to the external project KOS or approve product lifecycle advancement.

1. Read `README.md`, `docs/project/execution-baseline.md`, the exact active task and applicable ADRs before edits. Identify the role and scope; keep preparation, implementation, review and acceptance distinct.
2. The signed IZURE agreement and later approved written amendments govern scope. Restricted source contracts stay outside this repository; use safe section/decision references.
3. Before product work, verify the designated Git root/current candidate and the approved instruction/task binding required by the project KOS. Record missing evidence as `BLOCKED_MISSING_EVIDENCE`; do not manufacture an approval or lifecycle transition.
4. No PHI, patient identifiers, credentials, raw payloads, production logs or private source documents may enter Git, issues, PRs, examples or test artifacts. Use synthetic data only. Read source material narrowly and on demand.
5. No Dentrix/cloud/database connection, schema/migration, appointment write, provisioning, deployment or external communication is authorized by this scaffold. Follow the exact later task authorization and verified environment identity for such work.
6. Keep Dentrix behind its adapter, AI outside hard deterministic validation, and all writes behind explicit human approval plus scoped server validation. These controls remain implementation requirements, not completed behavior.
7. Follow `CONTRIBUTING.md`, `SECURITY.md` and the dependency-review gate. Preserve unrelated changes. Run the applicable checks and report what actually ran and what remains pending.
8. Keep independent review and verification tied to the same candidate; never mark client acceptance or compliance from an AI review or passing scaffold check.

No starter-kit installer or private parent workspace content should be copied into the product checkout. Confirm co-location or validated orchestration with the project owner before representing this entrypoint as KOS enforcement.
