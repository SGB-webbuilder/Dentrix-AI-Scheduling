# Deterministic rules

Future pure evaluation of authorized hard constraints and explicit office/provider rules. Each decision should produce a stable reason suitable for tests and a safe user explanation.

Rule precedence, effective dates, version changes, override permissions, duration defaults, and conflict handling are **PENDING CONFIRMATION**. A model's interpretation is a proposal until validated and, where required, confirmed by the authorized user. Hard constraints must be rechecked on the server immediately before a write is attempted.
